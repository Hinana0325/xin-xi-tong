# 刷机包检查清单（存档参考）

来源：Jiang 于 2026-10-29 发来的清单。状态：仅存档参考，先不按它做。
当前项目范围仍为 QEMU virt only，不做真机刷机包。此文件不作为验收标准。

## 一、设备与项目准备
[ ] 确认目标设备型号与代号 — 必须与目标机型匹配
[ ] 确认 Android / ROM 基础版本 — 记录版本号、构建号与来源
[ ] 确认分区布局与 A/B 槽位 — 确认是否采用动态分区
[ ] 确认 Bootloader / Fastbootd 刷写条件 — 明确哪些分区在哪种模式下写入
[ ] 备份原厂固件与重要数据 — 准备可验证的恢复方案

## 二、镜像文件
[ ] boot.img — 核对内核、ramdisk 与镜像格式
[ ] vendor_boot.img — 确认目标设备是否需要
[ ] init_boot.img — 确认目标设备是否需要
[ ] dtbo.img — 核对设备树覆盖配置
[ ] vbmeta.img / vbmeta_system.img — 核对 AVB 验证链及签名配置
[ ] super.img 或 system.img — 按实际动态分区布局准备
[ ] vendor.img / product.img / system_ext.img — 按设备实际分区准备
[ ] recovery.img — 仅在设备架构与刷写方案需要时准备
[ ] modem / bluetooth / dsp 等固件 — 仅按设备实际固件布局准备
[ ] 其他设备专用镜像 — 根据原厂包及分区表逐项核对

## 三、刷写脚本与配置
[ ] flash_all.bat — Windows 全量刷写脚本
[ ] flash_all.sh — Linux 全量刷写脚本（如提供）
[ ] 保留数据的刷写脚本 — 明确不擦除用户数据的行为
[ ] 清除数据的刷写脚本 — 明确擦除范围并设置保护
[ ] 分区映射表 — 每个镜像对应明确的目标分区
[ ] 设备型号检查 — 避免错误机型执行刷写
[ ] 命令返回值与错误处理 — 失败时停止，记录错误原因
[ ] 执行日志 — 记录设备、命令、结果和版本
[ ] 锁定 Bootloader 的操作审查 — 默认不自动重新锁定

## 四、固件完整性与安全
[ ] 所有镜像来源可追溯 — 记录来源、版本及提取方式
[ ] 镜像 SHA-256 校验 — 生成并核对校验值
[ ] AVB / 签名 / 防回滚检查 — 确认与目标设备的安全启动要求一致
[ ] 动态分区容量检查 — 确认逻辑分区布局和容量可容纳镜像
[ ] A/B 槽位处理检查 — 避免错误切换或破坏启动槽位
[ ] 用户数据擦除行为审查 — 默认保护用户数据，明确提示风险
[ ] 危险操作审查 — 检查 erase、format、lock 等命令

## 五、打包与交付
[ ] 目录结构完整 — 镜像与脚本路径一致
[ ] 压缩包可正常解压 — 无缺失文件或损坏
[ ] 脚本可识别路径与空格 — 兼容预期运行环境
[ ] 附带版本说明与适用机型 — 写明设备代号、版本和限制
[ ] 附带刷写说明与故障恢复说明 — 说明驱动、模式、失败处理
[ ] 最终包校验值 — 记录最终交付包 SHA-256

## 六、测试验收
[ ] 静态检查通过 — 文件清单、路径、哈希、分区映射
[ ] 脚本审查通过 — 无错误机型、错误分区或危险默认行为
[ ] 连接与设备识别测试 — Fastboot 能识别正确设备
[ ] 非破坏性检查通过 — 先验证设备信息与执行前置条件
[ ] 刷写过程测试 — 在可恢复的目标设备上验证
[ ] 首次启动测试 — 验证系统能完成启动
[ ] Wi-Fi / 蓝牙 / 蜂窝网络测试 — 按设备硬件适用性测试
[ ] 相机 / 音频 / 传感器测试 — 验证关键硬件功能
[ ] 重启与再次启动测试 — 检查启动槽位及持久性
[ ] 恢复方案测试 — 确认失败时存在可执行的恢复路径
